# Архитектура FixList

## Путь данных

1. **Ввод.** Сотрудник сдаёт отчёт об обходе (`service.save_inspection`) или пишет о проблеме свободным текстом (`service.analyze_text` → `service.save_record`).
2. **Извлечение (`backend/extract.py`).** LLM возвращает JSON по схеме `ExtractionResult`. Код проверяет:
   - `equipment_id` есть в `data/equipment.json`;
   - минуты простоя подтверждаются фрагментом исходного текста (`downtime_quote`);
   - причина, которой нет в тексте, удаляется;
   - уверенность ниже порога → поле на проверку.
   Без ИИ работает разбор по правилам с тем же контрактом.
3. **Диагностика (`backend/diagnose.py`).** Гипотезы причин только из `data/causes.json`, ранжирование по словам в записи и истории станка. Чужие `cause_id` отбрасываются.
4. **Аналитика (`backend/analytics.py`, только код).** Убытки = простой × стоимость часа + запчасти. Ритм поломок, сокращение интервалов, здоровье аппарата, прогноз следующей поломки, сравнение «до/после» внедрения мер.
5. **Экономика (`backend/advisor.py`).** Меры из `data/measures.json`, экономия и окупаемость по формулам. ИИ выбирает и объясняет меры; числа в его тексте сверяются с расчётом.
6. **Сводка и чат (`backend/briefing.py`, `backend/assistant.py`).** ИИ получает только факты из базы и пишет объяснение; числа и названия станков проверяются, иначе показывается ответ, собранный кодом.
7. **Обёртка над моделью (`backend/llm.py`).** REST-вызовы Gemini / OpenAI / Anthropic, JSON-вывод, проверка схемой Pydantic, до 2 повторов с текстом ошибки, перебор моделей при 404/503/тайм-ауте и ключей при 429/401, общий бюджет 30 секунд, журнал `llm_calls`.

## Данные

SQLite (`smena.db`, не в репозитории): `companies`, `users`, `leads`, `shift_logs`, `incidents` (статусы заявок), `inspections`, `recommendations`, `applied_measures`, `llm_calls`, `meta`. Во всех таблицах с данными есть `company_id`; текущая компания задаётся на каждый запуск сценария (`db.set_company`).

## Роли

| Роль | Разделы |
| --- | --- |
| Сотрудник | Отчёт об обходе · Сообщить о проблеме · Мои задачи · Спросить ИИ |
| Администратор | Панель задач · Спросить ИИ · Состояние оборудования · Сводка дня · Что ломается чаще · Деньги и экономия · История · Сотрудники |

Статусы заявки: «Ждёт одобрения» → «Решают сотрудники» → («Нужна помощь администратора») → «Решена».

## Безопасность

- Ключи API только в `.env`.
- PIN хранится как `соль$PBKDF2-SHA256`.
- Сессия переживает обновление страницы через подписанный HMAC-токен в адресе; секрет — в `.session_secret` (не в репозитории).
